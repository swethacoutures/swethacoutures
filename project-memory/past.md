## 1. What this project is

**Swetha's Couture — Business Management System**
A web app for a tailoring / couture (boutique stitching) business. It manages the
full operational lifecycle of a custom-tailoring shop:

- Customers and their order history
- Custom stitching **Orders** (made-for person, category, measurements, design images, staff assignment, materials)
- **Billing / Invoicing** (the most mature, client-approved feature)
- **Inventory** of fabrics/materials
- **Staff** management, attendance, salary, and per-staff billing/cost rates
- **Income & Expenses** + **ROI / profitability analytics**
- **Appointments** and **Alterations**
- Reports

- **Built by:** Dream Team Services (the dev team — current operator email: thedreamteamconsultancy@gmail.com)
- **Client:** Swetha's Couture
- **Started:** ~mid 2024 (project ~1 year old as of June 2026)
- **Status when this memory was created:** Billing works well and the client is happy with it.
  The client has now asked to **complete the rest of the project**.

## 2. How it was built (origin story)

- The `package.json` name is `vite_react_shadcn_ts` and the original README is the
  generic Lovable/AI-scaffold template. This strongly indicates the project was
  **bootstrapped by an AI app builder (Lovable-style)** and then iterated on heavily by hand.
- Development was **highly iterative and bug-fix driven**, especially around Billing.
  There are **90+ markdown "fix log" files** in the repo root (e.g.
  `BILLING_DROPDOWN_SELECTION_BUG_FINAL_FIX.md`, `BILL_ID_INCREMENT_FIX_COMPLETE.md`,
  `WHATSAPP_COUNTRY_CODE_FIX.md`). Each documents one fix iteration. They are historical
  notes, **not** current architecture docs.
- Multiple "FINAL", "COMPLETE", "FINAL_FIX" suffixes on the same topic show features were
  fixed repeatedly. Treat these as archaeology, not gospel.

## 3. Legacy / duplicate artifacts to be aware of (tech debt left from iteration)

These exist in `src/` and can mislead. The **live** version is usually the plainly-named one
wired into `src/App.tsx`:

- Billing pages: `Billing.tsx` (LIVE) vs `Billing_New.tsx`, `Billing_fixed.tsx`, `Billing_backup.tsx` (stale copies)
- `ROIDashboard.tsx` (LIVE) vs `ROIDashboard_backup.tsx`, `ROIDashboard_broken.tsx`, `ROIDashboard_test.tsx`
- `Appointments.tsx` (LIVE) vs `Appointments_backup.tsx`
- `InventoryTableView.tsx` vs `InventoryTableView_Fixed.tsx`
- `OrderItemCard.tsx` vs `OrderItemCard_New.tsx`
- Design canvas variants: `DesignCanvas.tsx`, `TestDesignCanvas.tsx`, `ToolDesignCanvas.tsx`
- Root-level throwaway debug scripts: `debug-pdf-serial-numbers.js`, `test-pdf-*.js`,
  `test-sequential-ids.js`, etc. (not part of the build)

> **Lesson:** Before editing a feature, confirm which file is actually imported in `App.tsx`
> / the routing, so you don't fix a dead copy.

## 4. Hard-won knowledge from past fixes (recurring themes)

- **Bill numbering:** Bills use a sequential human ID (`Bill001`, `Bill002`, …) generated by
  `generateBillId()` in `src/utils/billingUtils.ts`. It scans all bills, fills the first gap
  from 1. This was the subject of many "increment fix" logs — be careful changing it.
- **Dates are stored inconsistently** (Firestore Timestamp vs string vs `{seconds,nanoseconds}`).
  `formatBillDate()` / `formatDateForDisplay()` in `billingUtils.ts` normalize them. There is
  even a dedicated `/date-format-fixer` admin page and `fixDateFormats.ts` utility to repair data.
- **Duplicate bills** were a real data problem → `fixDuplicateBills.ts` + `/duplicate-bill-fixer` page exist.
- **Two bill data shapes coexist:** legacy `items: BillItem[]` and newer
  `products: Product[]` (Product → Description grouping). PDF/HTML generation handles BOTH.
  Don't drop the legacy path without a migration.
- **Bill schema migration:** `billMigration.ts` + `/billing-migration` page + `scripts/migrate-bills.js`.
- PDF/invoice generation is **DOM-string → html2canvas → jsPDF** (client-side), with lots of
  inline-styled HTML in `billingUtils.ts`. Serial-number visibility in the PDF was a repeated bug.
- Payment screenshots upload to **Cloudinary** (unsigned preset), not Firebase Storage. Required
  env vars or the feature silently breaks (see `CLOUDINARY_SETUP_*` logs).
- WhatsApp sharing builds `wa.me` links; **country code** handling caused repeated bugs.
